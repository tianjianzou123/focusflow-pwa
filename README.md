# FocusFlow Tasks — Geolocation React PWA

FocusFlow is the completed application for **COMP10013 Dynamic Web Technologies — Practice 06**. It is a responsive React to-do list that obtains the device location when a new task is added, displays the latitude and longitude beside that task, and preserves the result in local storage. It also retains the installable and offline-ready PWA work from Practice 05.

- **Live HTTPS app:** https://tianjianzou123.github.io/focusflow-pwa/
- **GitHub repository:** https://github.com/tianjianzou123/focusflow-pwa

## Practice 06 requirements completed

### Part 1 — Geolocation API

`App.jsx` defines `geoFindMe`, including success and error callbacks for `navigator.geolocation.getCurrentPosition`. Successful coordinates are formatted to six decimal places. Unsupported browsers, denied permission, unavailable locations and timeouts all leave the task usable and show a clear error.

### Part 2 — `lastInsertedId` and `nanoid`

- `lastInsertedId` is managed with `useState("")`.
- Each task ID is generated with `"todo-" + nanoid()`.
- A new task starts with `location: { latitude: "##", longitude: "##", error: "##" }` while the asynchronous location request is pending.

### Part 3 — `locateTask`

`locateTask(id, location)` maps the task list, finds the matching ID, replaces only that task's `location`, and updates React state. A functional state update prevents stale asynchronous results from overwriting newer tasks.

### Part 4 — Pass `geoFindMe` to `Form`

`App.jsx` renders:

```jsx
<Form addTask={addTask} geoFindMe={geoFindMe} />
```

### Parts 5 and 6 — Pass and display coordinates in `Todo`

`App.jsx` supplies `latitude` and `longitude` from each task's `location` object to `Todo.jsx`. The component displays the required text beside the title:

```text
| la 55.864237 | lo -4.251806
```

### Part 7 — `useState` and `useEffect` in `Form`

`Form.jsx` tracks task submission using the `addition` state. After `addTask(name)` stores the new ID, an effect calls `geoFindMe()` once and resets `addition` to `false`.

## Extra completed functionality

- Add, edit, complete, filter and delete tasks.
- Persist task text, completion and coordinates with a `usePersistedState` hook and `localStorage`.
- Handle refused location permission without losing the new task.
- Installable manifest with standard and maskable icon sizes.
- Manually written and registered service worker with versioned offline caching.
- Online/offline indicator and install prompt.
- Keyboard-accessible, responsive desktop and mobile interface.
- Automatic migration of tasks saved by the earlier Practice 05 version.

## Run and test locally

```bash
npm install
npm run check
npm run build
npm run preview
```

Open the local URL printed by Vite. In another terminal, run:

```bash
npm run test:pwa
```

Geolocation works on `localhost` and HTTPS secure contexts. The deployed GitHub Pages address uses HTTPS.

## Demonstrate the assignment in Chrome

1. Open the live app and choose **Allow** when Chrome asks for location access.
2. Enter a task and select **Add task**.
3. Confirm that `| la ... | lo ...` appears beside the new task.
4. Reload the page and confirm the task and coordinates remain.
5. To simulate a location, open DevTools → More tools → Sensors, select a preset or enter coordinates, and add another task.
6. In DevTools → Application, inspect the Manifest, Service Workers and Cache Storage sections.
7. In DevTools → Network, select Offline and reload to demonstrate the cached PWA.

If location was previously blocked, select the site-settings icon beside the address, change **Location** to **Allow**, then reload.

## Deployment

Every push to `main` runs the GitHub Actions workflow in `.github/workflows/deploy-pages.yml`, installs dependencies, runs ESLint, creates the Vite production build and deploys `dist` to GitHub Pages. GitHub Pages provides the HTTPS context required by the Geolocation API and service workers. Vercel is therefore optional rather than required.

## Important files

```text
src/App.jsx                 geoFindMe, lastInsertedId, addTask and locateTask
src/components/Form.jsx     addition state and useEffect trigger
src/components/Todo.jsx     latitude/longitude display and task controls
public/manifest.json        PWA installation metadata
public/service-worker.js    offline cache and network handling
public/icons/               complete installable icon set
tests/pwa-smoke.mjs         automated geolocation and PWA checks
```

Location data stays in the current browser's local storage; the application does not send it to a server.
